# PoC هسته مالی AZIZIPAY (دفتر کل دوطرفه + شارژ از صرافی)

این پوشه یک نمونه اجرایی از **هسته مالی پیشنهادی AZIZIPAY** است که پیش از شروع توسعه ساخته شده تا طراحی سند ۲ و استک سند ۳ با شاهد عملی تأیید شود.

## اجرا

```bash
cd prototypes/ledger_poc
python3 ledger_poc.py          # اجرای همه تست‌ها
python3 ledger_poc.py > RESULTS.txt   # ذخیره خروجی
```
بدون هیچ وابستگی بیرونی؛ فقط Python 3.11+. خروجی کامل در `RESULTS.txt`.

## چه چیزی و چگونه آزمایش می‌شود؟

| تست | موضوع | تضمین |
|---|---|---|
| ۱ | مسیر شاد (شارژ → پرداخت → بازپرداخت) | دفتر کل متوازن، مانده کش‌شده = مانده مشتق‌شده |
| ۲ | ۲۰۰ فراخوانی هم‌زمان تأیید یک شارژ | Idempotency: فقط ۱ سند، پاسخ‌های یکسان |
| ۳ | ۳۰۰ تأیید هم‌زمان یک کد با Barrier | کد یک‌بارمصرف: فقط ۱ موفق، بدون شارژ مضاعف |
| ۴ | ۳۰ پرداخت هم‌زمان از موجودی محدود | موجودی هرگز منفی نمی‌شود |
| ۵ | انقضا، سقف مبلغ/روزانه، اپراتور غیرمجاز، سقف شناوری صرافی | اعمال سیاست‌ها و محدودیت‌های انطباقی |
| ۶ | سند معکوس + تسویه | اصلاح بدون حذف سابقه؛ تسویه جدا از شارژ و غیرقابل‌تکرار |
| ۷ | صفرکردن مانده‌های کش‌شده | بازسازی کامل از دفتر کل (سناریوی بازیابی از بکاپ) |
| ۸ | گزارش تطبیق در سطح صرافی | قابل استخراج‌بودن اختلاف‌ها برای تیم عملیات |

## نقشه ذهنی کد

```
Money            → پول فقط با عدد صحیح (واحد خرد)؛ float ممنوع
Ledger           → حساب‌ها، ثبت سند دوطرفه، معکوس، بررسی یکپارچگی، زنجیره هش
WalletService    → مانده کش‌شده + نسخه (کنترل هم‌زمانی)
CashInService    → ایجاد کد، اعتبارسنجی توسط اپراتور، تأیید اتمیک، سقف‌ها، تسویه
PaymentService   → پرداخت و بازپرداخت از کیف پول
PartnerRegistry  → صرافی/اپراتور مجاز (نمونه‌ای از بررسی مجوز و سطح دسترسی)
```

## محدودیت‌ها (صادقانه)

- قفل سراسری درون‌پروسه‌ای برای شبیه‌سازی تراکنش به کار رفته؛ معادل واقعی آن در PostgreSQL: `BEGIN/COMMIT` + `SELECT ... FOR UPDATE` + قیدهای یکتایی و Triggerها.
- هم‌زمانی چندپروسه‌ای، Isolation Level، Deadlock و عملکرد واقعی دیتابیس در این PoC سنجیده نمی‌شود؛ این موارد در ماه ۲ و ۳ با تست‌های یکپارچه و k6 پوشش داده می‌شوند.
- این کد برای اثبات طراحی است، نه نسخه قابل استفاده در تولید.
